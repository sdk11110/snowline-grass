# 草场连续渲染修复

实玩报告的黑色断线主要出现在草丛覆盖边缘。旧逻辑将边缘实例的高度乘以fade，部分高度变成0；弯曲草片被拍到地面后仍有水平面积，且实例法线变换会除以零轴长度。这会形成异常法线及贴地争抢，表现为随移动出现的断续黑线。旧逻辑还在每移动10米时同步重新采样、构建并上传约2万簇草，容易产生耗时尖峰。

现在保留所有有效实例的正尺度。每根草有固定seed，使用距玩家的连续可见度在片元阶段渐隐；不再把草高度压到0。近身压伏仍保留最低高度。草坡小纤维按像素导数衰减，减少移动中的高频闪纹。地形接缝裙边和全局阴影没有被关闭。

`src/experience/meadow-stream.js` 缓存固定世界格，只处理进入和离开边缘的实例，使用局部buffer更新和有限缓存。每帧生成有时间/工作量预算；近景保留22叶×4段，中景为8叶×2段，远距离细节减负。初次进入时先把物理位置设到真实出生点，再分帧准备初始可见草圈，最后展开地图。地形LOD的材质由新增/移除事件即时维护，不再逐帧遍历约千个场景对象；移除网格也会释放适配层记录的引用。

## 检查

- `tools/test-meadow-stream.mjs` 使用真实DEM与Three对象，检查30帧/秒、25及45米/秒各两分钟的流送、覆盖、局部上传、固定坐标、正尺度、缓存、重生及初次准备。
- `tools/test-meadow-materials.mjs` 检查LOD与嵌套对象新增/移除、雪场恢复、销毁解绑、每根草seed和渐隐合同。
- 浏览器通过同一出生点持续按W滑行复测，未再观察到原边缘黑色断线，未捕获error级控制台消息。原有雪场与冲浪回归继续运行。

旧重建帧CPU平均约5.63毫秒、p95约6.47毫秒。新测试把工作分散到实际移动的每帧，具体分布见 `evidence/meadow-stream-tests.json`；这两个采样口径不同，不将它们相除声称整体FPS提升。GC、其它场景工作与GPU仍可能影响实际帧率。

`?perf=1` 可启用仅用于本地诊断的统计面板；正常地址不会创建面板或采样数组。浏览器前后记录分别在 `evidence/meadow-browser-before.json` 和 `meadow-browser-after.json`。两轮启动时的草场设备档位不同，旧渲染计数还仅包含最后一次后处理绘制，因此这些记录用于检查更新尖峰和运行状态，不作为严格GPU/FPS对照。以真实DEM的明确测试条件、有效实例无零尺度和实际视觉复测共同判断修复。
